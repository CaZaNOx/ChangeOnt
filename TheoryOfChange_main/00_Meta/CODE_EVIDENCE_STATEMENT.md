# Code Evidence Statement

The code does not prove ontology.

The code is an investigation into whether **candidate discovered necessities of unfolding** can be operationalized honestly enough to produce meaningful behavior across heterogeneous problems.

What the code can provide evidence for:
- **operational usefulness** — whether a CO-derived formalization helps guide behavior;
- **reduction claim** — whether CO recovers classical behavior in stabilized/collapsed regimes;
- **surplus claim** — whether CO adds something in more dynamic or structurally contested regimes;
- **behavioral consequence** — whether the derived operators produce the kinds of field behaviors the theory predicts;
- **cross-domain viability** — whether the same kernel family remains meaningful across very different local problem spaces without bespoke algorithmic redesign.

What the code does not establish by itself:
- metaphysical truth;
- a fully airtight philosophical derivation;
- final canonical status of every primitive or element.

Working rule
The project is not selecting arbitrary modules or mathematical styles. It is trying to discover what mechanisms of change unfolding are real. Engineering success must therefore not be overinterpreted as ontological confirmation; engineering failure may falsify an operationalization, and sometimes a derivation claim, but only after parity, honesty, and implementation faithfulness are checked.

# Goal State: CO-Aligned Kernel

## Canonical target

The CO kernel is not a classical policy wrapper or simple score aggregator. It is the problem-agnostic runtime that transforms public problem structure into continuation identity, burden operations, branch relations, field state, quotient/grey/recursion structure, and earned collapse.

Canonical execution loop:

1. boundary / adapter exposes public facts and candidate expressions;
2. CandidateSurface publishes candidate rows;
3. continuation identity construction derives pressure-signature branches;
4. burden interpretation and burden-operation typing produce branch-internal burden structure;
5. RelationSurface derives cross-branch relations from public burden/effect facts;
6. RecursiveContinuationField updates branch field state;
7. CollapseCertificate checks whether collapse is earned;
8. CommitmentSurface expresses earned collapse as native action.

## Prohibited active behavior

Canonical CO execution must not route through hidden solver logic, baseline policy rescue, greedy reward selection, first-legal action selection, uniform action selection, or any other non-CO rescue path. Missing evidence or malformed packets are contract violations, not opportunities to invent action scores.

## What counts as success for the architecture

The architecture is acceptable only when active traces show that public facts become burden operations and relations, those structures affect RCF and collapse certificates, and readout follows earned-collapse structure rather than a plain score maximum.

## Claim boundary

This document defines the target architecture. It does not claim performance superiority, final formula derivation, final quotient tolerance, full consciousness theory, or algorithmic novelty over known methods. Those claims require separate evidence.

# Dynamic shape and coarseness field

Overview:
This concept names the derived bridge between static problem-shape prior and a future dynamic relational-coarseness shape field.

Canonical statement:
- [[01_Statements/02_Outer_Formation/022A_S-DR-shape-space-directed-unfolding-from-change]]

Core distinctions:
- **Shape-as-such:** the invariant fact that structured continuation has some local relational-gauge organization.
- **Local shape-state:** the current formed organization of reach, admissibility, comparability, burden, regime signature, retention, and collapse.
- **CO-space:** the earned local field of reach/comparability/admissibility/burden, not primitive container-space.
- **Directed unfolding:** proto-sequencing from asymmetric contribution under retained trace, not a pre-given timeline.
- **Coarseness field:** the distribution of retained resolution across a local shape-state.
- **Point-as-ball:** a point as a thin collapse of a local region under a current gauge.
- **Dynamic shape update:** lawful deformation of local shape-state from public/retained trace and changed relation/burden/admissibility/coarseness.

Implementation status:
- Current code implements a static six-question shape prior and local shape-gauged commitment correction.
- It does **not** yet implement a persistent dynamic shape/coarseness field.

Open items:
- harden the first-pass DynamicShapeField implementation and formula grounding;
- define coarseness/projection-horizon quantities;
- specify how public action/result traces update shape without oracle leakage;
- connect future code to this concept without turning shape into a tuning patch.

## Domain-relative coarseness refinement

A single scalar coarseness is only a first-pass fallback. A bounded local unfolding can be fine-grained along one retained invariant while coarse along another. The dynamic shape field should therefore be read as a coarseness field: `coarseness_radius` is global fallback, while public relation/burden domains may carry domain-specific coarseness when those domains are already earned by trace. See `022C_S-DR-domain-relative-coarseness-field.md` and kernel doc `107_DOMAIN_RELATIVE_COARSENESS_FIELD.md`.

# Summary signal — loopiness (recursive self-return concentration)
## Claim (formal)
Loopiness is a compact runtime signal summarizing short-cycle propensity and recurrent self-return under current bend/closure conditions.

## Philosophical Translation (of formal claim)
Many closures can pile up before basic stability is reached. Loopiness is the rough summary the runtime carries when it needs to notice that repeated self-return is dominating.

## Philosophical Justification
[[S-DF-self-propagating-selective-retention]] clarifies the deeper issue: change carries and alters itself forward, and repeated self-return can become locally dominant. [[S-DF-selective-recurrence]] and [[S-DF-prm-bend-metric]] then make it legitimate for a bounded kernel to carry a compact summary of when recursive self-return is thickening into trapped or concentrated closure. Loopiness is therefore better treated as a derived summary signal than as a deepest primitive.

## Explanation (informal)
Loopiness should not be mistaken for the whole recurrence story. It is the boiled-down signal the runtime can carry when many closure structures need to be summarized quickly.

## Derivation (Philosophical)
- Change changes change; multiple re-entries and closures arise before local settling.
- A bounded local kernel cannot carry every closure explicitly at once.
- Therefore a compact summary of recurrent self-return is legitimate.

## Derivation (Formal/Logical/Mathematical)
```text
loopiness := summary(short-cycle return, repeated local re-entry, low-gain closure concentration)
```

## Clarifications / Further Context
- Better treated as a compressed summary than as a deepest primitive.
- Useful for breadth/depth scheduling and monitoring trapped re-entry.

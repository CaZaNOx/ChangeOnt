# 022C S-DR — Domain-Relative Coarseness Field

## Status
Draft derivation / first-pass clarification. This file refines the coarseness claim in `022A` and `022B`; it does not introduce a new deepest primitive.

## Claim
Coarseness is not adequately represented, in general, by one global scalar. A bounded local unfolding may retain fine differences along one emergent invariant while remaining coarse along another. Therefore coarseness should be understood as a field-like distribution of retained resolution across active relation / burden / invariant domains.

## Derivation sketch
1. A point is a thin collapse of a local region under a gauge.
2. A local region is not equally resolved in all respects. Retention is selective: some differences matter for continuation, while others are ignored, quotientable, or unavailable.
3. Once multiple operative invariants are retained, no single resolution value can faithfully describe all of them.
4. Therefore a local shape-state should include a global coarseness fallback plus domain-relative coarseness where active domains are already earned by public relation, burden, hiddenness/exposure, admissibility, or sequence evidence.

## Example
A human can be visually coarse at bacterial scale, moderately fine in visible color, nearly blind outside the visible spectrum, and comparatively fine in some memory / social-recognition domains. Calling this one coarseness value loses the structure that actually governs continuation.

## CO role
Domain-relative coarseness affects:

- when a relation-field may be treated as function-like;
- whether a difference is retained, collapsed, or quotientable;
- how much ambiguity remains grey;
- whether collapse is earned in one domain while another domain still demands resolution;
- how shape updates after repeated biased-but-still-successful unfolding.

## Boundary rule
Domain-relative coarseness must not create arbitrary hidden dimensions. Domains are admitted only when they are already present in public retained structure: relation-field domain, burden type, hiddenness/exposure, admissibility, or sequence/phase evidence. No native action names, family names, hidden state, baseline values, or reward hindsight may define a coarseness domain.

## Minimal implementation target
A first-pass kernel may keep:

- `coarseness_radius` as a global fallback;
- `coarseness_by_domain` as a bounded dictionary over active public domains.

This is not a full high-dimensional metric. It is a minimal anisotropic coarseness profile that prevents the kernel from assuming that fine resolution in one invariant implies fine resolution everywhere.

# Canonical core and investigation periphery

This note separates the current philosophical **core** from the still-open **investigation periphery**.

- operative difference

- gauge (kernel-resolution primitive)
- ReID (kernel-resolution primitive)

## Investigation periphery (retain, test, do not silently equalize)
These are retained because they may matter, but they should not be visually equalized with the strongest core until better derived or tested:
- MDL / compressibility as one candidate formalization of selective-retention economy
- residuation as one candidate formalization of remaining-transformation burden
- loopiness as a derived summary signal of recursive self-return rather than a canonical primitive
- EF router
- H_ID as a historical/rename-candidate header
- candidate/readout surfaces as runtime carriers only, not ontology core
- any weaker element families not yet re-hardened under the latest ontology

## Working rule
The philosophical text should state clearly when it is speaking from the canonical core, when it is speaking about retained but still-investigated periphery, and when it is naming runtime surfaces that are active implementation carriers but not philosophical primitives/elements.

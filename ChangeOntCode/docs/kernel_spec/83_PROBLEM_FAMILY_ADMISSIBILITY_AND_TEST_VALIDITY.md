## 1. Admissibility

In principle, any bounded problem family is admissible if it can be represented as bounded local unfolding with:

- public boundary;
- legal transformations;
- admissible/prohibited transitions;
- task anchor;
- observation channels;
- public/hidden distinction where relevant;
- public or parity-honest transition/effect facts;
- fair baselines.

A problem is not excluded because it is classical, static, simple, artificial, or conventional.

---

## 2. Evidential strength

Admissibility does not imply strong evidence. A family is evidentially strong only if it stresses declared CO mechanisms.

Examples:

```text
branch identity across actions
relation topology
quotient/equivalence
relief/cancellation
grey preservation
earned collapse
shape-regime modulation
public-boundary discipline
cross-family mechanism reuse
```

A family that can be solved by one-step scoring may still be admissible but weak evidence for RCF.

---

## 3. Required problem-family documentation

Before a family supports paper claims, document:

1. what bounded unfolding it instantiates;
2. public information and hidden information;
3. allowed translator facts;
4. forbidden leakage;
5. expected shape placement;
6. expected continuation-field pressures;
7. baselines and literature/algorithmic justification;
8. what would count as CO success;
9. what would count as CO failure;
10. what mechanism the family stresses.

---

## 4. Baseline rule

Baselines must be parity-honest. A baseline may be included as an oracle upper bound only when clearly labeled as such.

Hidden state may not be given to a baseline and then compared as if it were a fair public-state competitor.

---

## 5. Current status note

This contract does not invalidate existing families. It clarifies their evidential role and the documentation needed before final-paper use.

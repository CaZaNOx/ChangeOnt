# Element — EF — Router (experimental regime-routing and math policy)
## Claim (formal)
EF routes between dynamic regimes and algebra contexts using bend/volatility, compressibility, and temporal history; it emits regime and math-policy signals for downstream control.

## Philosophical Translation (of formal claim)
EF is the experimental layer that tries to decide how the kernel should currently think, not just what it should currently score.

## Philosophical Justification
[[S-DF-regime-shape-variation]] captures the deeper ontological issue behind routing: local unfolding can vary in how tight, open, spread, or self-reinforcing it is. However, the stronger claim that a dedicated router element is itself a canonical ontological bundle has not yet been fully earned. EF is therefore kept as an experimental control bundle that represents one current way of carrying regime-shape information into runtime policy.

## Explanation (informal)
EF is meaningful and implemented, but philosophically weaker. It currently sits between ontology and control architecture. That role can be useful without being fully canonical yet.

## Derivation (Philosophical)
- Distinct regimes plausibly call for different monitoring and algebra postures.
- Signals for drift, compressibility, and temporal history make that routing thinkable.
- But the project has not yet shown that a dedicated routing element is strictly forced rather than one possible control surface.
- EF therefore remains provisionally justified.

## Derivation (Formal/Logical/Mathematical)
```text
dyn := f(volatility_proxy, loopiness, phase)
math_context := g(compressibility, quantale_ready)
```
Emits dyn and math_context as explicit downstream inputs.

## Clarifications / Further Context
- Keep routing simple and explainable; avoid oscillations between regimes.
- EF should remain marked experimental and outside the canonical ontological core until a tighter derivation is supplied.
- It may ultimately belong closer to header/control architecture than to the ontological element core.

## Next Steps in Chain
- either derive EF more strongly,
- or demote it explicitly to a control-surface/helper status.

## Active-chain status
Band: experimental-control-surface.

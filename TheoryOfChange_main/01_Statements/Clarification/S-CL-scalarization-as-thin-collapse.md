# Scalarization as thin collapse

## Claim
A scalar runtime field is legitimate only when it is an explicitly controlled thin collapse of richer continuation structure for a bounded local operation.

Scalars are not the ontology. They are summaries that may be used only when the differences lost by compression are nonoperative for the local operation, or when the scalar is clearly marked as a provisional proxy.

## Examples
Fields such as these are not primitive reality:

```text
support
burden
field_debt
grey_pressure
collapse_readiness
relief_capacity
viability
```

They are permitted only as local summaries of richer structures: pressure signatures, public effects, branch relations, path density, hiddenness, burden trends, or admissibility constraints.

## Acceptance conditions
A scalar field needs:

1. source structure named;
2. operation requiring compression named;
3. differences discarded by compression identified;
4. reason those differences are nonoperative or deliberately provisional;
5. monotonic commitments documented;
6. constants classified;
7. telemetry and tests showing how the scalar contributes.

## Anti-classical warning
If scalarization replaces relation topology, quotient, cancellation, and grey structure, the kernel collapses into ordinary weighted scoring. A CO runtime may use scalars, but it must not hide the live structure it claims to preserve.

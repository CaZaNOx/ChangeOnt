# Regime Header — ID (historical label for intermediate / bridge regime)
## Claim (formal)
ID initializes an intermediate regime: moderate dynamicity, mixed classical/CO weighting, and a bridge posture that can move in either direction under runtime evidence.

## Philosophical Translation (of formal claim)
Hold the system between rigid thin collapse / classical-degenerate simplification and strong CO sensitivity until the evidence forces a stronger commitment.

## Philosophical Justification
[[S-DF-hdr-common]] defines the shared live regime state. Within that state, a midpoint/bridge regime is legitimate when the field is neither clearly classical-stable nor clearly in high structural drift. The historical name "ID" remains provisional because the deeper ontological process here is regime estimation, not a privileged identity box.

## Explanation (informal)
In the current subtree this is best understood as a bridge regime. It preserves the historical label for continuity with the code and earlier discussions, but the label should not be mistaken for a fully earned identity-specific mechanism.

## Derivation (Philosophical)
- Some regimes are ambiguous or transitional.
- A kernel should not force strong classical closure or strong CO sensitivity too early.
- Therefore an explicit bridge regime is legitimate.

## Derivation (Formal/Logical/Mathematical)
```text
if evidence is mixed and reopening pressure is nontrivial
but not yet decisive,
then choose ID-like bridge settings.
```

## Clarifications / Further Context
- From a stricter change-first ontology, the deeper mechanism is regime-estimation/modulation; the header label is partly for readers and implementation.
- Either rename this regime explicitly as bridge/intermediate, or derive a genuinely identity-centered version later.
